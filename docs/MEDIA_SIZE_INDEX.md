# 可靠大小与大文件优先（开发分支）

此功能不在已发布的 0.4.0 APK 中。目前实现 Android 的本地媒体索引读取；iOS 与缺少新原生模块的旧构建明确禁用大小排序，普通月份、相册和时间顺序不受影响。真机与 iOS 验证尚未完成。

## 使用与语义

照片或视频首页进入「整理范围」，可直接使用快捷预设（照片页提供「陈旧截图（30 天前 / 90 天前）」，视频页在 Android 上提供「大体积视频」），也可手动选择「大文件优先」并叠加相册和月份。确认开始新一轮，不重置既有整理决定。下一批沿用保存范围，恢复保留原批次顺序；新一轮先确认范围，不默默改为默认随机。

此外，在「AI 扫描 → 完全重复」页的字节级完全重复检测中，Android 同样复用 `PickPicMediaIndex` 读取精确 `_SIZE` 进行文件大小预分桶，仅对同字节大小且数量 ≥ 2 的候选照片读取原文件计算 SHA-256 哈希，不读取大小唯一的文件。

只排序系统索引提供的正数、精确整数字节大小。空、0、负数或超过 JavaScript 安全整数范围均为未知，不伪装成小文件。未知大小不会纳入此顺序，可切回其他顺序处理；结束状态不称整个图库已整理完。这里没有空间释放统计，不将索引大小冒充已释放空间。

## 原生边界

`modules/pickpic-media-index` 是项目自有的 Expo 本地模块，使用已安装的 Expo Modules Core，不新增模型、运行时库或权限。

- 仅支持 photo/video 与严格校验的系统媒体 ID；每次查询最多 200 个去重 ID。
- 查询对应 MediaStore 集合的 `_ID` 与 `_SIZE`，使用占位参数，关闭 Cursor。
- 不读取原文件、EXIF、名称、位置或路径，不拷贝云端文件，不联网，不写媒体库。
- Android 的媒体访问限制仍由系统提供程序执行；调用层在查询前后复核权限与相册，并按媒体/权限代次丢弃失效请求。
- 大小 Map 与排序计数只存在内存，不新增磁盘缓存。会话范围、ID 顺序与跳过项沿用 records 的 AES-GCM 保护；加密备份已升级为 **v2**（32 MiB 上限，支持跨设备内容指纹重绑定、保护相册与复核忽略，仍不导出整理会话）。

遍历索引分页，保留一页与一批候选资产对象；为跨相册去重保留 ID 集合，不能宣称内存完全与图库规模无关。读取失败、相册消失、坏分页和原生模块不可用均不能输出部分排序或空库完成结论。受限授权重新枚举，仍不能保证系统未报告的并发图库变化可被绝对检测。

上述“不读原文件/路径”的承诺限于新大小查询模块，不是整个 App 的媒体访问承诺。候选枚举仍沿用安装的 MediaLibrary：其 Android 源码会为视频通过 MediaMetadataRetriever 读取尺寸，也可能为缺少尺寸的图片读取文件头，即使 resolveWithFullInfo 为 false。因此不能宣称遍历完全不打开原文件；大小数值始终从索引读取，不通过读取文件内容来估算。大图库的视频元数据枚举耗时尚未实机测量，播放器/照片预览当然也需要读取用户明确查看的文件。

## 为什么不直接用已有文件信息 API

已检查安装的 Expo SDK 54 源码：legacy FileSystem 对部分 content URI 使用输入流 `available()`，它不是可靠的文件长度；未获得长度也不能当成 0 字节。为此使用系统已维护的大小索引，而不是遍历原文件来猜大小。

官方依据（核对日期 2026-10-03）：[MediaStore SIZE](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns#SIZE)、[OpenableColumns SIZE 的未知值约定](https://developer.android.com/reference/android/provider/OpenableColumns#SIZE)、[Expo 本地模块](https://docs.expo.dev/modules/get-started/)。系统索引可能受提供程序更新时机影响，不承诺等同于逐字节重新测量或真实可释放空间。

## 构建与验证

Expo 自动链接默认发现根目录的 `modules`。需要重新构建 development build 或 APK；只更新 JavaScript、Expo Go 或旧 APK 不会新增此原生模块。模块源码随仓库保存，不提交生成的 Android 构建目录。

自动化测试覆盖跨页大文件、跨相册去重、超过 4GB 的大小、日期与既有决定排除、未知值、坏游标、分页/原生失败、失效权限、受限重读、范围草稿及恢复的认证加密。测试中的原生提供程序仍是替身，不能替代实际桥接验证；独立模拟器构建与体验证据、最后一次完整检查及尚未验证范围见 ITERATION_CHECKPOINT.md。
