# 整理记录加密备份

此功能已自 `v0.5.0` 起包含在正式发布版中（当前基线 `0.5.1`）。入口为设置 → 数据管理。

## 包含什么

当前版本使用 **v2** 加密备份格式（同时兼容导入 **v1** 备份）：

- 包含照片与视频的已整理决定、照片收藏队列、待删除队列、**保护相册清单**以及**复核忽略清单**（模糊误报忽略、`similar_group`「此组不相似」稳定键）。
- 不包含原照片、视频、缩略图、地理位置、EXIF、扫描缓存、整理会话与界面偏好；不可访问或已不存在的媒体会跳过并报告数量。
- PickPic 不提供服务器、账号或自动云端同步；用户选择的系统文件提供程序可能自行将文件同步到其云盘。

v2 备份同时记录条目摘要与隐私化的跨设备内容指纹（文件名、分辨率、时长与已知文件大小的 SHA-256 摘要及创建时间容差），不以明文写出文件名或路径：

- **同设备恢复**优先按原 ID 与元数据摘要精确匹配；
- **跨设备/重装恢复**仅在内容指纹 **1 对 1 唯一匹配**时自动重绑定，存在多个候选（歧义）时安全跳过并计入 `ambiguousSkipped`；
- **「此组不相似」忽略项**会同时保存本机快照键与按排序成员内容指纹生成的设备无关稳定键（`sgc1:...`），重扫及跨设备恢复后不再反复弹出；
- **保护相册**优先按本机相册 ID 或唯一标题匹配，并阻止受保护相册内的媒体在恢复时被加入待删除队列；无法自动匹配的保护相册会明确提示用户手动核对。

恢复前先解密校验并预览可恢复、已有决定、待删除、跨设备重绑定、保护相册、忽略记录及跳过数量；确认时重新核对权限与元数据。当前决定优先，待删除队列默认不恢复，恢复过程不会请求系统删除。

## 文件保护

- 文件内容使用 AES-256-GCM 加密并认证。密码通过 scrypt 派生 32 字节密钥，参数固定为 N=65536、r=8、p=2，工作内存约 64 MiB。参数固定于文件格式版本，导入文件不能自行调低或调高计算成本。
- Android/iOS 的密码派生使用 Quick Crypto 的原生异步 scrypt，文件格式与参数不变；便携 JavaScript 实现用于独立算法测试。原生模块不可用时停止操作，不悄悄降级算法或参数。原生计算本身不能中途终止；取消会关闭界面，使结果失效，并在计算返回后清零、丢弃密钥，不保存或恢复数据。
- 每次导出通过 Expo 原生异步安全随机数接口生成新的 32 字节盐和 12 字节 nonce；随机数不可用时停止导出，不回退到 Math.random。
- 文件头仅含格式标记、盐和 nonce，不包含媒体 ID、记录数、路径、分类或日期。整个文件头参与认证。明文以 64 KiB 块填充，降低从精确文件长度推断记录数量的可能；文件总长度仍然可见。
- 至少 12 个字符的密码并不能保证高强度。建议使用较长、独立的口令。密码无法找回，也没有后门或服务端解密钥匙。
- 密钥、编码明文和解密字节缓冲区在结束时清零；密码、解密对象不持久化、不写日志。JavaScript 字符串和垃圾回收不能保证内存被立即或彻底擦除。
- 导入文件通过 `DocumentPicker` 关闭 `copyToCacheDirectory` 先校验 `asset.size <= 32 MiB` 上限再读取，避免误选大视频在 Android UI 线程同步拷贝引发 ANR；导出临时文件只含密文并在完成后删除。
- 导入上限为 **32 MiB 密文负载**、50,000 条整理记录、1,000 个保护相册与 50,000 条忽略记录。先验证认证标签，再解析严格白名单格式；错误密码、篡改、非法字段和不兼容版本不会写入整理状态。

## 保护相册与分域失密自救

- **三层保护相册防线**：未筛选相册时默认跳过受保护相册媒体；所有队列入口（卡片、模糊/相似/完全重复、备份恢复）均拦截受保护项；物理删除前再次实时核对保护相册成员，核对失败时失败关闭（Fail-Closed）阻止删除。
- **分域失密自救向导**：隐私门禁区分系统密钥库不可用（Keystore）、本地密库解密失败（SQLCipher）与索引结构异常（Schema），提供重试、**先验密后恢复 `.pickpic` 备份**（自动校验照片与视频权限）与**二次确认重置本地隐私索引**。重置前先阻断新写入并排空所有持久化队列（`mediaProgressStorage`、`settingsStorage`、`changeTracker`），再关闭数据库并清理密文与密钥，且绝不触碰相册原照片或视频。

## 应用内部存储边界

导出密码保护与本机设备保护是两套独立机制。自 `v0.5.0` 起，整理记录、待删除/收藏队列与设置的持久化快照采用 AES-256-GCM，大体积整理进度/待删队列与扫描索引采用 SQLCipher 按行加密存储。记录、设置、扫描数据库分别使用随机设备密钥，通过 SecureStore 的 Android Keystore / iOS Keychain 保护，不存于普通文件。密码导出格式、参数及匹配规则不变，导出文件不依赖原设备密钥。

旧 AsyncStorage 快照先加密写入、读回认证并核对内容后移除旧键；扫描旧库先导出到加密库、验证完整性及所有用户表数据，并完成旧库 WAL checkpoint，之后才清理精确的旧库及附属文件。失败保留原数据。读取密文失败、设备密钥缺失或合并错误会关闭整理界面，不能用默认状态覆盖；写入失败保留内存里的最新操作并提供重试。请勿卸载或清除数据来解决此类错误，卸载会丢失本机恢复所需的密钥。设备密钥真的丢失时，仅凭本机密文不能找回记录。

Android 配置禁止应用自动备份，并在云备份及设备迁移规则中排除私有数据；iOS 配置设备专用 Keychain 并排除 Documents / Application Support 目录备份，但 iOS 尚未原生验收，厂商第三方备份行为不能由此保证。图库权限、系统媒体数据库和原始照片并不由 PickPic 加密。浏览器没有本实现所需的设备安全存储与 SQLCipher，明确停在不支持页面，不退回明文存储，已有浏览器数据不被清除。

相册 Expo Image 预览使用内存缓存，启动时清理其历史磁盘缓存及应用拥有的 ImageManipulator 临时目录；清理失败不开放整理。图像处理期间仍有必要的明文临时图片，崩溃/强杀后的残留只能在下次启动尝试清理。没有加密系统相册、媒体提供程序或第三方 SDK 的所有缓存，未承诺安全擦除旧存储块、内存取证防护或防止 Root/越狱后的运行时访问。ML Kit 的度量通信边界见 AI_MODEL_RESEARCH.md。

扫描期间生成的灰度缩放图或分类裁剪图删除失败，同样关闭隐私门禁并停止后续扫描；启动、续扫与分类补扫在缓存故障未解除时不能继续。已提交的基础扫描结果保留，未处理项不会冒充完成。重试先等待正在结束的扫描，再清理上述自有缓存；成功后恢复界面，由用户继续任务。不清理整个应用目录、原图库或用户备份。自动化故障注入验证处理中的失败与停止；独立模拟器的缓存目录权限夹具验证原生门禁及恢复，不冒充真实设备磁盘故障。

## SDK 日志补丁维护

应用错误日志仅保留通用阶段，不输出原始异常中的媒体 ID、路径、分类标签、数据库内容或密钥。SDK 补丁仅替换已审查的日志参数；保留原生媒体读取、成功返回、Promise 拒绝与 SDK 错误状态，不以隐藏日志代替错误处理。

`npm ci` / `npm install` 的 postinstall 执行 `scripts/apply-privacy-patches.js`。当前覆盖 ML Kit core / face-detection / image-labeling 5.0.0（含 Android Kotlin、iOS Swift 与 JS/TS 文件）和 expo-media-library 18.2.1 共 **14 个**完整源码或编译文件；支持重复执行。使用 `node scripts/apply-privacy-patches.js --check` 验证安装结果，并配合 `node scripts/check-privacy-config.mjs` 静态校验权限、备份排除与源码构建配置。禁用安装脚本的环境必须显式应用补丁并检查后再构建。

Android 的 `package.json` 自动链接配置要求 `expo-media-library` 与 `expo-image` 从源码构建。否则 Expo 预编译库可能绕过本地媒体日志补丁，或带入详细图片加载日志。图片模块沿用其默认 `ALLOW_GLIDE_LOGS=false`，不要开启 `EXPO_ALLOW_GLIDE_LOGS`；验收应核对自动链接解析、实际 Gradle 模块和 APK 内编译配置，不能仅凭 node_modules 指纹或构建成功判断补丁生效。其余模块不因此全部改为源码构建。

版本、替换锚点及 LF 规范化后的完整文件 SHA-256 均需匹配；所有输入先验证，再写入，未知版本或同版本源码变化会明确失败。升级依赖时应审查原始差异与业务行为、更新补丁和指纹、运行隐私回归并重建原生包；不能仅刷新指纹来消除失败，也不能静默跳过补丁。生成的 node_modules 不提交 Git，补丁脚本、版本锁和测试提交。

此措施不是所有第三方库或操作系统日志的全局净化保证。系统诊断、原始图库和 ML Kit 度量通信仍有各自边界；不承诺设备永不联网或 Root 后无运行时信息。

导入先将 v2 保护相册与复核忽略表写入 SQLCipher，再提交合并后的媒体记录快照并等待 `flushMediaProgress()` 持久化完成才提示成功；若持久化失败则自动回滚内存快照并保持隐私写入门禁提示，原照片、视频始终不受影响。重试会重新核对当前记录并尝试保存。无明文临时恢复日志。

## 验证

自动化测试覆盖实际加密算法，并使用 Node.js crypto 独立解密；覆盖错误密码、盐/nonce/正文/标签篡改、随机数失效、取消、格式与容量限制、恢复合并、排除待删除、权限变化以及持久化失败后重试。平台文件接口通过替身验证，不能据此宣称所有文件提供程序和厂商机型都通过。

新依赖包含 expo-crypto、expo-document-picker、react-native-quick-crypto 及其 Nitro/base64 依赖，已有 development build 必须重新构建原生部分。相册备份只查询索引元数据，并显式关闭 resolveWithFullInfo；不调用会额外读取位置/EXIF 的 Android 详情接口，也不请求位置权限。真机验证按用户安排延期；iOS 原生构建尚未验证。

Quick Crypto 与 Nitro 固定匹配的生成代码版本；Android 的配置插件只让这两个新增库继承应用已经选定的 AGP/Kotlin 版本，不改写其他模块，不硬编码另一个 SDK 工具链，也不修改 node_modules 源码。配置改写有幂等测试，API 37 独立模拟器的 x86_64 Release 构建与运行已通过；不等同于 ARM64/iOS 构建验收。

原生代表流程已验证：真实导出文件经独立 Node 解密确认含测试记录，错误密码不恢复，正确密码先预览再确认；恢复后计数立即正确。测试只使用独立模拟器内一张合成图片，不覆盖大图库、全部系统文件提供程序或真实设备。

本机加密验证（2026-10-03，开发分支）：独立 API 37 x86_64 模拟器覆盖升级后，旧合成整理决定、扫描结果和设置仍可用，旧扫描明文库及附属文件已清理，新库不能用普通 SQLite 读取；AsyncStorage 旧键迁为认证密文。原生篡改媒体密文、移除 records 密钥槽位、通过 SQLite 触发器模拟拒绝写入均进入保护界面，失败记录未被覆盖；恢复各自完整的测试副本后启动正常。自动化另覆盖保持应用开启后重试最新决定，使用真实 AES 算法和真实 Zustand。真机/iOS、真实存储满以及大图库性能不是这些测试的已证明范围；ARM64 最终构建验收另见 ITERATION_CHECKPOINT.md。

设计依据：[Expo SDK 54 Crypto](https://docs.expo.dev/versions/v54.0.0/sdk/crypto/)、[Expo DocumentPicker](https://docs.expo.dev/versions/v54.0.0/sdk/document-picker/)、[noble-ciphers](https://github.com/paulmillr/noble-ciphers)、[noble-hashes](https://github.com/paulmillr/noble-hashes)、[Quick Crypto scrypt](https://margelo.github.io/react-native-quick-crypto/docs/api/scrypt)、[OWASP 密码存储参数建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。使用成熟库不代表这套应用集成已经取得独立安全审计认证。
